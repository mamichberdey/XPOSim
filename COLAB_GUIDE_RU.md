# XPOSim в Google Colab: оценка фокуса CRL

Готовый ноутбук: [Открыть в Colab](https://colab.research.google.com/github/mamichberdey/XPOSim/blob/c0064f57d16a607b3b971533eaff3410cbf1f6db/notebooks/CRL_Focus_Colab.ipynb).

Он устанавливает недостающие зависимости, загружает закреплённую версию XPOSim и таблицы материалов, показывает формы параметров, рассчитывает фокус и формирует архив. Miniconda и `environment.yml` для этого сценария не нужны. Ноутбук доступен до слияния PR: ссылка указывает на конкретный commit.

## 1. Первый запуск

1. Откройте ссылку выше и войдите в свой Google-аккаунт.
2. Выберите **Файл → Сохранить копию на Диске**, если хотите сохранять собственные настройки. Общий исходный ноутбук при этом не изменяется.
3. Для первого запуска оставьте CPU. Для GPU выберите **Среда выполнения → Сменить среду выполнения → Аппаратный ускоритель → GPU**; названия пунктов зависят от языка интерфейса. Выберите любой доступный GPU. После смены среды снова выполните подготовку.
4. Выберите **Среда выполнения → Выполнить все**. Параметры по умолчанию дают рабочий пример с бериллиевой CRL. В необязательной ячейке восстановления оставьте флажок выключенным.
5. Первая ячейка проверит NumPy, SciPy и Matplotlib. Если виден GPU, но CuPy отсутствует, она попробует установить колесо CuPy 14.2.0 для обнаруженной CUDA 12/13. Существующие драйверы и CUDA Toolkit не заменяются. Затем небольшой FFT проверит фактическую работоспособность GPU.
6. Дождитесь таблицы и четырёх графиков. Сообщение `CPU / NumPy` означает, что расчёт идёт на процессоре. Для параметра backend «Автоматически» это нормальный рабочий вариант.

Google Colab требует доступ к интернету для загрузки кода. Доступность GPU, длительность сессий и лимиты определяются Colab и не гарантируются проектом. См. [официальный FAQ](https://research.google.com/colaboratory/faq.html).

## 2. Как менять параметры

Меняйте значения в форме ячейки **2**, затем повторно выполняйте ячейки **2 → 3 → 4**. Установочную ячейку в той же сессии повторять не требуется.

| Поле | Смысл и единицы |
| --- | --- |
| `geometry` | Цилиндрическая CRL — 1D; осесимметричная CRL с круглой апертурой — 2D |
| `source` | Точечный источник на заданном расстоянии либо плоская волна |
| `energy_kev` | Энергия фотонов, кэВ |
| `source_distance_m` | Расстояние от источника до **входа** CRL, м; для плоской волны не используется |
| `material_preset` | Материал вместе с плотностью: Be, Si, Al или алмаз |
| `custom_formula`, `custom_density_g_cm3` | Используются только для своего материала; плотность в г/см³ |
| `radius_um` | Радиус кривизны каждой параболической поверхности, мкм |
| `aperture_um` | Полный диаметр/ширина апертуры, мкм |
| `bridge_thickness_um` | Минимальная толщина материала между поверхностями одного элемента, мкм |
| `n_elements` | Целое число элементов CRL |
| `accuracy` | «Быстро» или «Точнее»; меняет численную сетку |
| `scan_start_mm`, `scan_stop_mm` | Для своего диапазона: расстояния от **выхода** CRL, мм |
| `scan_points` | Число точек основного скана; около максимума выполняется дополнительное уточнение |
| `grid_points` | Число отсчётов по каждой оси; 0 — автоматический выбор |
| `window_factor` | Ширина расчётного окна / апертура; должна быть больше 1 |
| `batch_size` | Число одновременно считаемых детекторных плоскостей; 0 — автоматический выбор |

**1D и 2D — разные физические модели.** Переход к 1D не является способом повысить скорость расчёта осесимметричной линзы с сохранением той же физики. Для одной геометрии сравнивайте «Быстро» и «Точнее».

По умолчанию рассчитывается идеальная центрированная CRL. Входная амплитуда равна единице и ограничена номинальной апертурой. Карты дефектов, конечный размер источника и полихроматичность не входят в этот первый ноутбук.

## 3. Как читать результат

- **Найденный максимум** — положение максимальной пиковой интенсивности среди рассчитанных плоскостей. Это выборка с локальным уточнением, а не гарантированное решение непрерывной оптимизации.
- **Аналитическая оценка** использует геометрическую модель CRL с учётом расстояния до источника. Дифракционный максимум может отличаться.
- **FWHM** — ширина на полувысоте. В 2D приводятся срезы по x и y через максимум. Наименьшая FWHM и наибольшая интенсивность могут находиться в разных плоскостях.
- **Пропускание** — отношение выходной мощности к входной после ограничения апертурой, в конечном расчётном окне. Это не абсолютный поток фотонов источника.
- **Интенсивность** дана в относительных единицах. Абсолютный поток требует отдельной нормировки источника.
- Автоматический скан охватывает 0,5–1,5 аналитического расстояния. Пик на границе означает, что интервал следует расширить.

Для примера по умолчанию ожидается фокус приблизительно в **1,13 м от выхода CRL**. На проверенном CPU-расчёте FWHM порядка **1,04 мкм в 1D** и **1,22 мкм в 2D**; небольшие изменения зависят от сетки и положения детекторных плоскостей.

## 4. Проверка численной точности

Автонастройка сетки использует дифракционную оценку размера пятна и ограничивает размер для экономии памяти. Это эвристика, а не подтверждение сходимости. Проверки границ и шага тоже не заменяют проверку сходимости.

1. Сравните «Быстро» и «Точнее» для одной геометрии и одинакового скана.
2. Если появилась диагностика ограничения сетки, задайте большее `grid_points` вручную и проверьте устойчивость FWHM.
3. Отдельно увеличьте физическое окно. Например, удвойте `window_factor` и `grid_points` одновременно, сохранив шаг. Увеличение только окна ухудшает разрешение.
4. Увеличьте число точек скана и проверьте устойчивость положения максимума.
5. Сопоставьте изменения с точностью, которая нужна для вашего эксперимента.

Физические ограничения модели: скалярное монохроматическое излучение, малые углы, отсутствие поляризационных эффектов и обратных отражений.

## 5. Сохранение и повторный запуск

В ячейке **4** включите `download_zip` и выполните её. Архив можно также скачать через левую панель **Файлы → xposim_results**. Содержимое:

- `configuration.json` — параметры для следующего запуска, длины в SI;
- `metadata.json` — результаты, диагностика, версии Python/зависимостей и точный commit XPOSim;
- `focus_scan.csv` — расстояния, пиковая интенсивность и FWHM;
- `arrays.npz` — численные массивы лучшей плоскости и центральных продольных профилей;
- `focus_report.png` — изображение отчёта.

Для повторения включите флажок в необязательной ячейке восстановления, загрузите один `configuration.json` или `metadata.json`, затем запустите ячейки **3 → 4**. Восстановление заменяет конфигурацию в памяти, но не переписывает видимые значения формы. Фактические материал и модель показаны в таблице результатов. Для возврата к форме отключите восстановление и вновь выполните ячейку 2.

Хранилище сессии Colab временное. Скачайте нужные архивы до отключения среды. Сохранение копии ноутбука на Google Диск не сохраняет автоматически все файлы его временной сессии.

## 6. Если что-то не работает

| Ситуация | Что сделать |
| --- | --- |
| GPU недоступен | Продолжить на CPU или запросить другую сессию GPU в Colab |
| GPU выбран, но используется NumPy | Проверить сообщение первой ячейки; после смены среды выполнить подготовку заново. При ошибке CuPy можно начать новую сессию; не устанавливать одновременно несколько вариантов пакета CuPy |
| Ошибка загрузки GitHub | Проверить интернет и повторить первую ячейку; завершённые загрузки кэшируются в сессии |
| Сообщение об отсутствии реального изображения | Увеличить расстояние до источника или изменить линзу; проверить число элементов |
| Недостаточно памяти | Задать `batch_size = 1`; уменьшение сетки допустимо с последующей проверкой точности |
| FWHM не определена или есть предупреждение о сетке | Уточнить сетку/окно и посмотреть профиль |
| Максимум на границе скана | Выбрать свой, более широкий диапазон |
| После подготовки изменена версия модуля | Снова выполнить форму параметров, чтобы создать конфигурацию текущей версии |

## 7. Как автору публиковать и развивать набор ноутбуков

Текущая структура:

```text
XPOSim.py                       # физика, готовый сценарий и диагностика
xray_material_data/             # данные для материалов
notebooks/CRL_Focus_Colab.ipynb  # формы, графики, сохранение
COLAB_GUIDE_RU.md                # этот гайд
```

Расчётный интерфейс:

```python
import XPOSim as xpos

config = xpos.CRLFocusConfig(
    energy_kev=12,
    material_formula="Be",
    density_g_cm3=1.848,
    radius_m=50e-6,
    aperture_m=100e-6,
    bridge_thickness_m=30e-6,
    n_elements=10,
    source_distance_m=15,
    geometry="cylindrical",
    backend="auto",
)
result = xpos.estimate_crl_focus(config)
print(result.peak_z_m, result.fwhm_at_peak_m)
```

В библиотеке все длины в метрах. Ноутбук переводит удобные для пользователя мкм и мм в SI. Массивы `CRLFocusResult` возвращаются как NumPy независимо от backend; сохраняется одна полная детекторная плоскость и центральные профили, без полного стека 2D-полей.

Для обновления публичной версии:

1. Проверить изменения XPOSim и сохранить их отдельным commit.
2. В установочной ячейке обновить `SOURCE_REF` на полный SHA этого commit и `SOURCE_SHA256` на SHA-256 файла `XPOSim.py`. Нельзя закрепить ноутбук на SHA его собственного commit: сначала фиксируется код библиотеки, затем ноутбук.
3. Выполнить ноутбук с чистой сессии: CPU 1D, CPU 2D и GPU при наличии. Проверить экспорт и повторную загрузку параметров.
4. Сохранить ноутбук без выводов ячеек, персональных путей и секретов в публичный GitHub-репозиторий. Этот ноутбук не содержит доступа к приватным данным и не требует токенов.
5. Для кнопки Colab использовать URL вида `https://colab.research.google.com/github/OWNER/REPO/blob/NOTEBOOK_COMMIT/notebooks/CRL_Focus_Colab.ipynb`. `NOTEBOOK_COMMIT` — commit, уже содержащий ноутбук. Такой URL воспроизводим и не зависит от изменений ветки.
6. Обновить кнопку в README и этот гайд. После проверки можно выпустить тег версии и использовать его в ссылке на ноутбук.
7. Каждый новый ноутбук строить вокруг отдельной задачи. Общие расчёты и диагностику добавлять в XPOSim, а в ноутбуке оставлять формы, представление результата и экспорт.

Текущая проверка: ноутбук целиком выполнен в локальном Jupyter-ядре на CPU для обеих геометрий, с загрузкой закреплённого кода из GitHub и проверкой архивов. Проверены сценарий XPOSim и прежние CPU-проверки. Интерфейс самого Google Colab, его файловая загрузка и ветка CuPy/CUDA требуют отдельного прогона в сессии Colab с GPU.
