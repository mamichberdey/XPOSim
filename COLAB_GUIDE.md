## Focusing and calculation grid

Focusing dimensionality describes the parabolic lens surfaces; it is independent of numerical-grid dimensionality.

| Focusing | Grid | Model |
| --- | --- | --- |
| Line focus (1D) | 1D | Parabolic profile focusing along x |
| Line focus (1D) | 2D | The same x-focusing profile with finite structure depth along y |
| Point focus (2D) | 2D | Axisymmetric parabolic surfaces focusing along x and y |
| Crossed CRLs (2D) | 2D | An x-focusing CRL followed by a separate y-focusing CRL rotated by 90° |

The structure-depth input is enabled for line focusing on a 2D grid and for each crossed stack. Both two-axis modes select a 2D grid automatically.

CRL dimensions are entered in µm, photon energy in keV, density in g/cm³, and source distance in metres. Source distance is measured to the CRL entrance. The axial coordinate z is measured from the CRL exit. Displayed units adapt to the range.

### Align two crossed CRLs

Choose **Crossed CRLs (2D)** and set the geometry and material of the x and y stacks separately. The notebook starts with 6 elements in the x stack and 58 in the y stack. Both use the same default geometry and silicon. The isometric layout shows the element count above each stack. The y element is shown from above, with the blue face on top. **Source-to-CRL distance** runs to the x stack entrance. **Inter-stack gap** measures the free space from the x stack exit to the y stack entrance. A gap of zero places the stacks in contact.

**Auto-align** finds the smallest nonnegative gap for which both paraxial images lie at the same downstream z. The calculation uses the ray-transfer matrix of each stack, including its axial length. Along y, the source-to-stack distance includes the length of the x stack and the gap. Along x, propagation continues through the gap and the length of the y stack. The form and the report use the y stack exit as z = 0 for both image positions.

**Manual** evaluates the gap you enter. The isometric layout indicates a common image plane or separate line images and shows a suggested gap when available. **Axial alignment tolerance** sets the permitted separation of the predicted images. With no physical auto-alignment solution, adjust the lens parameters or enter a manual gap to simulate an astigmatic configuration with a downstream image.

The wave calculation propagates through the rectangular pupil of each stack and the free space between them. The numerical peak intensity and the minima of the x and y FWHM curves are wave-optical quantities. The **Equivalent aperture area** multiplies the x stack's rectangular entrance area by the simulated transmission of the pair. The material preview shows single-stack analytical quantities for each CRL.

For an extended source, the plane of maximum intensity depends on both the point-source diffraction pattern and how the different source points overlap at that z. For the default crossed pair with the Gaussian source, the common paraxial image is near 13.92 mm from the y stack exit. The peak-intensity curve is broad around that position. The **Peak** button, the numerical readout and the blue curve use the full selected source. The sampled FWHM minima along x and y are listed separately.

The simulation summary shows the **Equal-FWHM position** from the y stack exit. The search refines crossings and near-contact points of the full-source x and y FWHM curves inside the scanned interval. It reports the closest resolved match to the numerical peak, with a relative difference of at most 0.1%. The result is available as `result.equal_fwhm_plane` with fields `z_m`, `fwhm_x_m` and `fwhm_y_m`. An unresolved match is returned as `None`.

```python
from XPOSim import CRLFocusConfig, CRLStackConfig, analyze_crossed_crl, estimate_crl_focus

config = CRLFocusConfig(
    geometry="crossed", material_formula="Si", density_g_cm3=2.33,
    radius_m=6.25e-6, aperture_m=50e-6, bridge_thickness_m=2e-6,
    n_elements=6, structure_depth_m=30e-6, source_distance_m=15.0,
    second_crl=CRLStackConfig(radius_m=6.25e-6, n_elements=58, structure_depth_m=30e-6),
    gap_m=None,
)
alignment = analyze_crossed_crl(config)
print(alignment.gap_m, alignment.image_x_m, alignment.image_y_m)
result = estimate_crl_focus(config)
```

## Plane-wave, point and Gaussian illumination

**Plane wave** supplies a coherent field with uniform unit amplitude and constant phase inside the entrance pupil. Source distance and FWHM inputs are disabled. The preview shows the back focal distance. In the Python API, use `source_type="plane"`. The API sets `source_distance_m` and each magnification component to `None`.

A point source has a finite source-to-CRL distance and spherical phase. A Gaussian source is spatially incoherent, centered, and specified by its intensity **FWHM**. The form defaults to 100 µm along x and 1000 µm along y. A 1D grid uses the x width. Zero width represents a point-like source along that axis.

Two methods are available:

- **Intensity convolution** convolves the central-point intensity with the projected Gaussian at each z. For crossed CRLs, the kernel uses the beam-core displacement measured on each source axis by propagating an off-axis wave through both stacks, including their finite pupils and absorption. The measured displacement is interpolated linearly in z and used to scale the source FWHM. Single-stack calculations use the ray-transfer scale. Convolution approximates each off-axis response by a shifted central response. Direct sampling also accounts for changes in shape and transmitted intensity. The Accurate evaluation window accounts for the projected source widths across the scan interval.
- **Incoherent point sampling** propagates each source point through the pupils and adds its weighted intensity. Crossed CRLs sample equal-probability Gaussian cells, with points centered in the cells and scaled to preserve the Gaussian variance. The independent default counts are 7 along x and 21 along y. Each extra point along one axis increases the total number of modes by the other axis count. A zero-width axis uses one point.

For crossed CRLs, a sampling warning identifies axes where the geometrical central source-point spacing projected onto the numerical reference plane exceeds half the computed coherent FWHM. Increase the count on that axis and compare FWHMs and profiles on the same propagation grid. **Model, mesh and diagnostics** lists the Gaussian kernel widths for convolution or the geometrical projection and the actual point counts for point sampling. In Python, `source_points` sets the x count and the optional `source_points_y` sets the y count. `result.source_mode_counts` and `result.projected_source_fwhm_at_peak_m` report these values.

## Geometry-based adaptive grid

The initial transverse window encloses the aperture and, where applicable, structure depth, with a default minimum width of 1.3 times each geometric extent. Point counts account for diffraction width and phase variation and use FFT-friendly factors 2, 3, 5 and 7. Actual spacings are selected first as readable multiples of 5 nm, with 0.5 nm, 0.05 nm, etc. quanta below 5 nm; the window/count then adapt to preserve coverage. Automatic counts allow a small FFT-friendly margin near 110% of the nominal cap when that preserves the finer rounded spacing. They do not silently change the displayed step while retaining an unrelated computational step.

**Fast** uses the propagation grid directly for field samples. **Accurate** evaluates the propagated complex field on a dense transverse evaluation grid using inverse Fourier chirp-z transforms, targeting at least 24 samples across the coherent diffraction-width estimate, within bounded sizes. This calculates the field at detector coordinates; it does not smooth an intensity image. It avoids enlarging the entire 2D grid just to resolve a nanometre-scale intensity peak.

Accurate evaluation spacings are quantized separately, rounding down when possible while preserving a bounded evaluation grid size and its propagation-window limit. Dense field sampling cannot recover frequencies missing from the entrance grid. Accurate also increases the propagation-grid budget. Actual propagation-grid point counts and steps are shown beside the computed CPU/GPU backend. Two-dimensional counts are displayed as x × y. When Accurate uses a separate transverse evaluation grid, the status reports its counts and steps too. The library's corresponding accuracy values remain `preview` and `refined`.

With **Adapt propagation window**, edge-power probes can enlarge automatic axes independently while preserving the resolution target. Explicit point-count overrides retain user control. Window expansion and field evaluation sizes have memory limits. Check boundary warnings and compare finer grids, larger windows and more source nodes when quantitative accuracy matters. Automatic settings do not certify convergence.

## Peak-intensity position and calculation region

`find_peak_intensity_distance` accepts a callable giving the transverse peak intensity at distance z. It expands a three-point bracket with variable steps and refines a local maximum with bounded scalar optimization. It consumes no precomputed z array and returns a `PeakIntensitySearchResult`.

The notebook's **Peak-intensity position** locates the largest transverse intensity in the selected calculation region. A crossed-CRL run reports the full beam. The minima of the x and y FWHMs and the paraxial image position can occur at other distances.

The finite-source analytical image distance is the **first evaluated point** and seeds the local basin. Default search bounds are 0.05–3 times that distance. Several diffraction maxima can exist; this is a local search, with no global-maximum guarantee. Boundary or unresolved maxima appear in diagnostics.

For a Gaussian source, the central coherent point sets the automatic axial ROI. Preparation of the full source reuses the coherent field and follows that first search. A single-stack calculation uses the central point as its reference and lists the sampled full-source peak under **Model, mesh and diagnostics**.

For crossed CRLs, the optimiser checks the full beam across the scan, includes any paraxial image positions in that interval, and refines the strongest candidate. The search uses the same transverse region as the displayed curves. If the scan resolves a stronger peak, the report uses the strongest sampled plane. Direct Gaussian point sampling always selects the strongest computed plane without additional evaluations of the ensemble. A **sampled** label identifies that resolution.

**Calculation region → Auto** uses the beam to select the sampled region.

1. The axial display ROI follows the coherent peak intensity down to **Axial ROI intensity fraction**, default 0.2 of the coherent peak.
2. The interval is sampled on a uniform lattice anchored at the numerical maximum. **Target z sample count** controls this lattice independently of the preceding search.
3. Significant transverse intensity across that interval defines a padded x/y ROI, with default threshold 0.01 of its maximum.

**Calculation region → Manual** takes z bounds in mm from the CRL exit, and x/y bounds in µm from the optical axis. A 1D grid uses x alone. The automatic peak search is limited to the selected z interval, with its initial guess clamped to that interval. The uniform z lattice stays within the requested bounds. Fast selects native samples. Accurate evaluates the field on a local transverse evaluation grid that can be shifted off axis. Metrics and plots use the selected transverse region. The crossed-CRL peak search also uses it. Transmission and effective aperture use the full exit field. For two-axis focusing, the longitudinal maps use the x and y samples nearest the optical axis.

In Python, set `scan_range_m=(zmin, zmax)` and `detector_roi_m=(xmin, xmax)` in 1D, or `detector_roi_m=((xmin, xmax), (ymin, ymax))` in 2D. API coordinates are in metres. **Peak search tolerance** controls the optimizer's axial tolerance.

## Calculation progress and time estimates

Compute displays a stage progress bar, completed work, elapsed wall time and **ETA for this stage**. Stages cover grid/window preparation, central-point peak search, axial ROI, preparation of the full Gaussian source and its cached modes, transverse field sampling, final metrics and rendering. Completion collapses to a compact elapsed-time indicator so the results workspace keeps its height. Errors leave a visible stopped state. Updates run synchronously in the existing computation callback, without threads or timers.

For a stage with a known total, ETA is estimated from elapsed time per completed item. Detector-plane progress advances after a completed batch and its metric reductions, rather than forcing each plane into its own batch. This preserves GPU batching. Estimates can change as timings accumulate and do not promise an exact completion time.

Adaptive peak/ROI searches do not know their eventual number of evaluations. They show activity and evaluation counts with **ETA: estimating · adaptive stage**, without inventing a percentage or treating the maximum evaluation budget as a fixed workload. The ETA for a known stage excludes later stages; a precise whole-calculation forecast is not available before the adaptive work has resolved its grid and display interval.

The Python API accepts `estimate_crl_focus(config, progress=callback)`. The callback receives an immutable `CRLProgressUpdate` with `stage`, `completed`, `total`, `elapsed_s`, `stage_elapsed_s`, `eta_s` and `detail`. Unknown totals and estimates are `None`. Omitting the callback retains the existing numerical behavior. Observer exceptions propagate to the caller.

## What batches on the GPU

In Auto mode, a successful CuPy FFT probe selects CuPy. Selecting PyTorch or JAX runs field arithmetic, FFTs, Fourier zoom and Gaussian filtering with the selected GPU backend. The completed calculation reports the backend and device used.

- Point-source, plane-wave and Gaussian-convolution display scans process independent z planes in batches, sharing the exit spectrum. Fast and Accurate sampling both support these batches.
- Direct incoherent point sampling batches the independent source modes through the CRL and to each detector plane, then sums weighted intensities. Its z planes are currently visited sequentially; mode batches provide the parallel work at each z.
- CuPy and PyTorch size automatic batches from available VRAM. JAX uses a conservative 64 MiB working-memory target. All three cap automatic batches at 16 planes. **Batch size** in advanced controls overrides the heuristic. CPU automatic batches default to one.
- Point sampling prepares the exit spectra once and reuses them for the scan and slider. The cache uses VRAM, then host RAM, then private temporary storage as needed. Each detector plane reads the cached spectra in bounded batches. Temporary spectra are released with the calculation session.
- Consecutive CRL elements depend on the preceding field, and adaptive peak/ROI steps depend on previous evaluations, so these are sequential. Each field evaluation can still use GPU-parallel array operations and source-mode batches. Plot rendering and scalar optimization orchestration stay on the CPU.

## Effective aperture and transmission

**Effective aperture** describes the useful opening after absorption in the curved lens surfaces. The analytical model normalizes the integrated intensity to the on-axis free-space intensity at the CRL exit and excludes the uniform loss in the webs. It reports a width for line focusing and an equivalent diameter for point focusing. Published definitions of effective aperture use different normalizations. [Effective aperture of X-ray compound refractive lenses (2017)](https://journals.iucr.org/s/issues/2017/03/00/mo5159/)

**Equivalent aperture from transmission** in **Model, mesh and diagnostics** expresses the simulated transmitted fraction as the width or diameter of a clear opening under uniform illumination. It includes absorption through the webs. The transmitted fraction scales aperture area for a point-focus lens and aperture width at the same structure depth for a line-focus lens.

The exit power is summed on the full propagation grid before field resampling and display cropping. Free propagation conserves power over the full transverse plane, so the equivalent aperture from transmission is independent of z. Incoherent point sampling integrates the weighted exit powers of all modes during the existing source batches. The convolution model uses the central point's power under its shift-invariant approximation.

For a single stack, `result.effective_aperture_m` returns a width or diameter in metres. For crossed CRLs, `result.equivalent_aperture_area_m2` returns an area in square metres. `result.summary()` records the convention as `integrated_transmission`. The low-level `crl.effective_aperture()` applies the entrance pupil to the supplied coherent field and returns the equivalent width or diameter, or `None` when no power enters the pupil. Use `beam_metrics(crl.E(), crl.grid).fwhm` for the exit beam's half-maximum widths.

Other frontends, or a changed Colab theme after calculation, can use the explicit selector; if an Auto probe is unavailable the previous palette is retained. The actual Colab frontend remains a separate integration check.

### Setting physical grid steps

Enable **Show scan region and sampling settings**, then find **Sampling and peak search**. **Transverse grid control** offers Auto, Set spacing or Set point counts. Spacing targets are entered in nm; inactive counts/spacings keep their values but are ignored. Targets and fixed-count windows use the same readable-spacing policy; actual propagation counts and steps are reported beside the backend. Explicit spacing control has a 4096-point per-axis limit in 2D or 65536 in 1D; larger requests fail clearly rather than overriding the target silently. Existing explicit point-count overrides remain available.

**Axial grid control → Set spacing** enables Target Δz in mm. Auto uses the target sample count; Fast rounds the target spacing upward and Accurate downward to the preferred sequence **1, 2.5, 5 × a power of ten**. A manual target uses the nearest preferred spacing, e.g. 0.04 mm → 0.05 mm. The origin is the **full-precision numerical peak-intensity position**, so $z_k=z_{\mathrm{peak}}+k\Delta z$. Only Δz is rounded; z values retain the computed offset. With a reference of **30.93 mm** and a step of **0.05 mm**, the grid includes **30.83, 30.88, 30.93, 30.98, 31.03 mm**. The code uses the unrounded reference, even when its displayed label has fewer decimals. Automatic bounds expand outward on this lattice with nonnegative z. Manual samples stay within the interval. The maximum is 10001 displayed planes; the exact reference is a regular sample, not an extra point inserted between samples. Thus Δz is the real common spacing of every adjacent overview plane. Actual Δz and the number of planes appear beside the backend, with the propagation grid and, in Accurate mode, the separate transverse evaluation grid.

In the API use `grid_step_x_m`, `grid_step_y_m` and `scan_step_m`; a transverse step and point count for the same axis are mutually exclusive. `scan_points` is a target count rather than an exact count after rounding. `result.scan_step_m` and summary metadata `scan_grid_uniform` and `scan_anchor_m` describe the actual lattice. `peak_index` indexes the **exact numerical reference** in that lattice. `reference_metrics`, `best_intensity` and `fwhm_at_peak_m` refer to the exact optimized distance, evaluated independently of the lattice. An independently refined peak does not depend on the display step. When the crossed workflow uses a sampled peak, the axial step determines its resolution and the selected point is still on the same uniform lattice.


Image-plane magnification is the signed source displacement scale −B(z)/source distance from the discrete-stack ray model, evaluated at the **analytical image distance** in cell 2. The display reports magnification along the focusing axes. The print report also includes this estimate. It does not follow the numerical z slider. In the API, the unfocused y entry describes the source displacement scale through free propagation. The low-level API still supports other planes through `CRL.source_magnification(z, source_distance)` and `result.plane_at(z).magnification`; `result.magnification_at_peak` remains available.

## Reusable Python API

```python
import XPOSim as xpos

config = xpos.CRLFocusConfig(
    geometry="one-dimensional",
    grid_dimension=2,
    structure_depth_m=50e-6,
    source_type="gaussian",
    source_fwhm_x_m=5e-6,
    source_fwhm_y_m=5e-6,
    source_method="convolution",  # or "points"
    peak_search_tolerance_m=1e-6,
    backend="auto",
)
result = xpos.estimate_crl_focus(config)
search = result.numerical_peak  # Central-point reference for a Gaussian source.
plane = result.plane_at(search.z_m * 1.01)
print(result.analytical_image_distance_m, result.magnification_at_peak)
print(result.effective_aperture_m)  # Flux-equivalent width or circular diameter.
```

For Gaussian illumination, `result.numerical_peak.intensity` evaluates the full source for crossed CRLs and the central point for a single stack. `result.peak_intensity` and `result.fwhm_m` describe the full source. `peak_z_m` and `fwhm_at_peak_m` refer to the numerical reference plane. `result.sampled_peak_z_m` gives the full-source maximum among displayed samples. `result.sampled_fwhm_minimum_z_m` gives one distance per focusing axis. For crossed CRLs, `result.coherent_reference` preserves the initial coherent result used for the scan estimate. Summary metadata records `peak_search_basis`, `peak_search_initial_z_m`, `peak_search_sampled` and `axial_roi_basis`.

All API lengths are metres. `find_peak_intensity_distance(objective, initial_z_m, ...)` also works independently of the CRL workflow. The older `find_numerical_focus` wrapper emits a `DeprecationWarning`; `NumericalFocusResult`, `result.numerical_focus`, `result.analytical_focus_m`, `result.magnification_at_focus` and `focus_tolerance_m` remain compatibility aliases. New summary keys use `peak_search_evaluations`, `peak_search_converged`, `analytical_image_distance_m` and `magnification_at_peak`. The workflow names `CRLFocusConfig`, `CRLFocusResult` and `estimate_crl_focus` remain available.

`CRL.apply_to_fields` handles bounded batches of independent source fields. `CRL.source_magnification` and `CRL.ray_transfer_matrix` expose the discrete-stack ray model. Established low-level NumPy/CuPy interfaces are retained.

## Limits and validation

- Intensities are relative. Incident amplitude is one within the nominal entrance pupil. Transmission is finite-window output power divided by power after that pupil.
- The model is scalar, monochromatic and paraxial. It excludes polarization, back-reflections and high-angle propagation.
- For memory errors, reduce batch size first. Reducing grid sizes reduces accuracy. Direct source integration can be considerably more expensive than convolution.
- An unresolved FWHM means the required half-maximum crossings were not found within the numerical window.
- If inputs are missing, open the current notebook and run cell 2 explicitly. A previously opened notebook or Drive copy does not automatically receive repository updates: use the current link at the top of this guide. If widgets themselves do not render, rerun setup in a fresh session and allow the standard custom-widget manager.
- Colab session memory is temporary. Reopening starts with the parameter form; restarting a kernel loses entered values.
